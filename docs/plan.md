# 企業イベントリスト作成プロジェクト計画

## 1. 目的

このプロジェクトの目的は、指定された条件に合致する企業のイベント情報を収集し、ExcelまたはGoogleスプレッドシート形式のリストとしてまとめることです。将来的には、情報収集とリスト更新の自動化を目指します。

- **収集対象とするイベント:** (例: 特定業界の展示会、オンラインセミナー、記者発表会など、具体的に記述)
- **リストに含める項目:** (下記は例。必要に応じて追加・削除)
    - 企業名
    - イベント名
    - 開催日時 (開始・終了)
    - 開催場所 (オンライン/オフライン、住所/URL)
    - イベント概要
    - 公式サイトURL
    - 参加費用
    - 申し込み締め切り
    - 情報取得元URL
    - データ取得日時

## 2. 情報収集戦略

どのようにしてイベント情報を集めるか、具体的な方法を検討します。

- **情報源の特定:**
    - イベント情報ポータルサイト (例: Connpass, Peatix, Techplay)
    - 企業の公式ウェブサイト (プレスリリース、イベント告知ページ)
    - ニュースサイト
    - SNS (Twitterなど)
    - (その他)
- **収集手段:**
    - **Webスクレイピング:** Pythonのライブラリ (Beautiful Soup, Scrapyなど) を利用して、ウェブサイトから情報を抽出します。サイトの利用規約を遵守する必要があります。
    - **API利用:** イベントサイトや企業が提供するAPIがあれば活用します。
    - **RSSフィード:** 更新情報をRSSで配信しているサイトがあれば利用します。
- **Gemini APIの活用:**
    - **情報抽出:** 収集したテキストデータ（イベント概要、ニュース記事など）から、開催日時、場所、参加費用などの**構造化データ**を抽出します。
    - **概要生成:** 長いイベント説明文から、指定した文字数程度の**簡潔な要約**を生成します。
    - **カテゴリ分類:** イベントの内容に基づいて、事前に定義したカテゴリ（例：セミナー、展示会、交流会）に**自動分類**します。
    - **関連情報検索:** イベントに関連する企業情報や過去の類似イベントなどを検索させ、付加情報として加えることを検討します。

## 3. データ形式と出力

収集した情報をどの形式でまとめるかを決定します。

- **出力形式:** Google スプレッドシート または Excel (.xlsx)
    - Google スプレッドシートは、共有やAPI連携が容易なため推奨されます。
- **データ構造 (列定義):**
    - `企業名`: テキスト
    - `イベント名`: テキスト
    - `開催開始日時`: 日付/時刻形式 (例: `YYYY-MM-DD HH:MM`)
    - `開催終了日時`: 日付/時刻形式 (例: `YYYY-MM-DD HH:MM`)
    - `場所_種別`: "オンライン" or "オフライン"
    - `場所_詳細`: テキスト (住所や会場名、オンラインの場合はURLなど)
    - `概要`: テキスト (Gemini APIで生成した要約を含めることも検討)
    - `公式サイトURL`: URL形式
    - `参加費用`: テキスト (例: "無料", "5,000円")
    - `申込締切`: 日付形式 (例: `YYYY-MM-DD`)
    - `情報取得元URL`: URL形式
    - `取得日時`: タイムスタンプ形式

## 4. 実装計画 (ステップ)

具体的な開発手順を段階的に示します。

1.  **環境構築:** Python実行環境、必要なライブラリ (requests, beautifulsoup4, google-api-python-client, openpyxl など) のインストール。Gemini APIキーの取得と設定。
2.  **情報収集モジュールの開発:**
    - 各情報源に対応するスクレイピングまたはAPIクライアントのコードを作成します。
    - 収集した生データを一時的に保存する仕組み (ファイルや簡単なDB) を検討します。
3.  **Gemini API連携モジュールの開発:**
    - 収集したデータを受け取り、Gemini APIにリクエストを送信して情報抽出、要約、分類などを行う関数を実装します。
    - APIリクエストの効率化（バッチ処理など）やエラーハンドリングを考慮します。
4.  **データ整形・出力モジュールの開発:**
    - 収集・抽出した情報を、定義したデータ構造に合わせて整形します。
    - Google Sheets API または `openpyxl` を使用して、スプレッドシート/Excelファイルに書き込む処理を実装します。
    - 重複排除のロジックを組み込みます。
5.  **自動化とスケジューリング:**
    - スクリプト全体を定期的に実行する仕組みを構築します (例: Windowsタスクスケジューラ, Linux cron, Google Cloud Scheduler)。
6.  **テストとデバッグ:** 各モジュールの単体テスト、全体の結合テストを実施します。
7.  **ドキュメント作成:** 最終的なコード構成、使い方、設定方法などをまとめます。

## 5. 技術スタック (候補)

- **プログラミング言語:** Python 3.x
- **Webアクセス:** `requests`
- **スクレイピング:** `Beautiful Soup 4`, `Scrapy` (大規模な場合)
- **Gemini API:** `google-generativeai` ライブラリ
- **Google Sheets連携:** `google-api-python-client`, `gspread`
- **Excel操作:** `openpyxl`, `pandas`
- **データ処理:** `pandas` (任意)
- **バージョン管理:** Git

## 6. 考慮事項

- **情報源の利用規約:** スクレイピングを行う際は、対象サイトの `robots.txt` や利用規約を確認し、遵守します。短時間に大量のリクエストを送らないよう配慮が必要です。
- **情報の鮮度:** 定期実行の頻度をどの程度にするか検討します。
- **エラーハンドリング:** サイト構造の変更、APIのエラー、ネットワーク問題などに対応できるようなエラー処理を実装します。
- **APIコスト:** Gemini APIの利用料金を考慮し、効率的なAPIコールを心がけます。
- **機密情報管理:** APIキーなどの機密情報は、コード中に直接記述せず、環境変数や設定ファイルなどで管理します。
